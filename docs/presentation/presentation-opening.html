My choice: give the assistant access to the full feature path, with explicit package boundaries and shared checks.

OPENING / DATA FLOWAI QUIZ GENERATOR

Two paths, one durable source of truth

Generation creates an immutable playable quiz; submission records one deterministic result.

Create

Topic + URL
→ validate and fetch safely
→ normalize + hash + bound context
→ generate + validate + ground
→ atomic quiz persistence

Play & submit

Public quiz without keys
→ start attempt + private bearer token
→ submit option IDs
→ authorize, validate, grade, finalize
→ stored result with answer review
The browser never receives a pre-submit answer key and never supplies an authoritative score.

OPENING / SCORINGAI QUIZ GENERATOR

The LLM never grades the learner

The assessment formula is implemented as isolated, deterministic TypeScript policy.

Per question

Single: correct = 4; wrong = 0.
Multiple: 1 point per correctly selected option, capped at 4.
Wrong selections add 0; no deduction.
Policy is provisional because the task is ambiguous.

Final score

weight(i) = 1.1 ** i, starting at i = 0.
score = Σ(scoreᵢ × weightᵢ) / Σ(weightᵢ).
Store on the 0–4 scale.
Round score and percentage only for display.
Consequence: an all-correct multi-select sitting may score below 4; selecting every option is not penalized.

OPENING / TRUSTAI QUIZ GENERATOR

Every boundary has a different risk

Runtime validation, network restrictions, public projections and transactions protect different parts of the flow.

Remote content & model

HTTPS / public IP / redirect checks.
512 KiB body cap; bounded timeouts.
Markdown is untrusted source data.
Structured output + domain validation + excerpt checks.

Browser & persistence

Public DTOs omit keys and excerpts.
Random attempt token; only its hash is stored.
Option ownership checked before grading.
Atomic, idempotent finalization; sanitized logs.
Prompt instructions reduce injection risk; they do not prove semantic correctness or complete resistance.
